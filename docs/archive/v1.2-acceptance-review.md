## Gaps remaining before calling v1.2 "fully per-spec"

The three v1.2 **success criteria** are met (paste a string and see it on the
grid; export a created range into readable notation; understandable parser
errors). Two items from the v1.2 **feature list** are not implemented:

1. **Rank-only shorthand `AK`** (meaning both `AKs` and `AKo`) is not parsed.
   `isValidHand` is strict membership over the 169 canonical hands, so a
   suffix-less non-pair token like `AK` is rejected with a clear error. The
   manual checklist and tests already treat `AK` as invalid. Low effort to add
   if desired (expand a suffix-less non-pair token to its suited + offsuit
   pair).
2. **One-click "Copy to clipboard"** is not implemented. The deterministic
   notation is shown in a read-only "Current range" field the user can select
   and copy manually, but there is no copy button. Small, self-contained
   follow-up.

Neither blocks the v1.2 success criteria; both are tracked here for honesty
against the literal roadmap feature list.

## Known risks / technical debt

Carried forward from the v1 review and still applicable:

- **localStorage write errors are unguarded in the UI.** Reads degrade
  gracefully (corrupt/invalid data → `[]`), but `saveSavedRange` can throw
  (quota exceeded, Safari private mode) and `App.tsx` has no try/catch or
  user-facing error. Low likelihood at current data sizes.
- **Single-device persistence.** Data lives only in this browser's
  `localStorage`; clearing site data loses ranges. No export/backup file yet
  (roadmap v3.2).
- **`PokerHand` is a bare `string` alias.** Validity is enforced at runtime via
  `isValidHand` / `classifyHand` guards rather than by the type system. Guards
  are thorough but the type itself is permissive.
- **Mobile functional but not optimized.** Fluid grid scales down, but 13-column
  tap targets get small at narrow widths. Mobile-first work deferred (v3.1). The
  new notation `<textarea>` inputs are usable but not specifically tuned for
  mobile.
- **Unused scaffold assets.** `src/assets/hero.png`, `react.svg`, `vite.svg`
  are unreferenced. Harmless; trivial cleanup.

New in v1.2 (low severity):

- **Notation parsing is case-sensitive.** Tokens must use canonical casing
  (uppercase ranks, lowercase `s`/`o`). `aks` or `77+` typed as `77 +` is
  rejected. Acceptable for now; case-insensitive parsing is deferred (below).

## Recommended next slice

Ship v1.2 as-is and begin **roadmap v1.3 (scenario metadata)**. Suggested first
slice: **add an optional `metadata` object to the `SavedRange` type plus an
editor section to set it**, starting with the lowest-risk, highest-value
fields — **position** (UTG/HJ/CO/BTN/SB/BB), **action type**
(open/call/3-bet/4-bet/defend/jam), and a free-text **notes** field. Keep it
self-contained:

- Extend `src/types/range.ts` with an optional `metadata` field (optional keeps
  existing saved ranges valid — no migration needed).
- Surface metadata in the editor and as a one-line summary on `RangeLibrary`
  cards.
- Add storage/round-trip tests proving old metadata-less ranges still load.

This is the natural next step in the roadmap's "study organization" phase, is
backward-compatible with existing `localStorage` data, and sets up v1.4 library
filtering/search. Defer the two v1.2 feature gaps above (`AK` shorthand, copy
button) to a small polish slice unless they are explicitly prioritized first.

## Explicitly deferred items

These are intentionally **not** in v1.2 and are noted to set expectations:

- **Compact notation formatter** — `formatRangeNotation` emits a full
  comma-separated canonical list, not compact forms like `77+` / `A2s+`. (The
  comment in `rangeNotation.ts` notes this is intentional for now.)
- **Case-insensitive notation parsing** — not implemented; canonical casing is
  required.
- **Weighted / mixed-frequency / action notation** — not supported; tokens with
  `:` or `@` throw a clear "not supported yet" error (roadmap v2.3 / v4.2).
- **Persisted practice stats** — practice stats are session-only; no
  persistence, history, or mistake review (roadmap v2.1+).
- **Mobile / PWA polish** — responsive but not mobile-optimized; no PWA/offline
  (roadmap v3.1).
- **Accounts / backend / cloud sync** — local-only; no auth or server
  persistence (roadmap v3).
